# Generated id columns Implementation Plan

> **For agentic workers:** executed inline with superpowers:executing-plans; steps use checkbox syntax.

**Goal:** New tables start with a database-generated `id` column, chosen from a toolbar preference (integer, uuid, none).

**Architecture:** A `generated` flag on `Column` in the core, expressed by the dialect and the generator; a separate app-settings preference in the web, applied by `addTable`.

**Tech Stack:** unchanged (TypeScript, node:test, React, Zustand, Playwright).

**Spec:** `docs/superpowers/specs/2026-10-01-generated-id-columns-design.md`

## Global Constraints

Same as `docs/superpowers/plans/2026-10-01-slice-1-draw-to-ddl.md`: Node 24 from mise (`export PATH="$(mise where node)/bin:$PATH"`), `.ts` import extensions, `erasableSyntaxOnly`, Biome style (`pnpm lint:fix` before each commit), tests in `src/tests/{unit,integration}`, no component rendering tests, no hand-written memoization, the core stays platform-free, conventional commits with the `Co-Authored-By: Claude Sonnet 5.5` trailer.

## Review Focus

1. A project saved before this change (columns without `generated`) loads and generates the same DDL. [Task 1]
2. A hand-edited project with `generated: true` on a `text` column loads (it is a draft) and the DDL is refused with the issue. [Task 1]
3. The settings value missing, not JSON, with an unknown `newTableId`, or storage that throws: the default is used, nothing crashes. [Task 2]
4. Changing a generated column to a type that cannot be generated clears the flag. [Task 4]
5. A table created with the preference on `none` is empty exactly as before. [Task 3]

### Task 1: Core — generated columns

**Files:** modify `packages/core/src/schema/types.ts`, `schema/validate.ts`, `dialects/dialect.ts`, `dialects/postgres.ts`, `sql/generate/generate-ddl.ts`, `project/parse-project.ts`, `index.ts`; tests in `tests/unit/schema/validate.test.ts`, `tests/unit/dialects/postgres.test.ts`, `tests/unit/project/parse-project.test.ts`, `tests/integration/sql/generate-ddl.test.ts`.

**Interfaces — produces:** `Column.generated?: boolean`; `GENERATED_COLUMN_KINDS`; issue code `generated-unsupported-type`; `Dialect.generatedClause(type: ColumnType): string | null`.

- [ ] Write the failing tests: validate flags `generated` on `text` and accepts it on `integer`, `bigint`, `uuid` and when absent; postgres `generatedClause` returns `GENERATED BY DEFAULT AS IDENTITY` for integer and bigint, `DEFAULT gen_random_uuid()` for uuid, `null` for text; the generator emits `"id" integer NOT NULL GENERATED BY DEFAULT AS IDENTITY` and `"id" uuid NOT NULL DEFAULT gen_random_uuid()`, a generated non-key column keeps its nullability rule, and a schema without `generated` produces the exact output it did before; `parseProject` keeps `generated: true`, accepts an absent field (a project saved before), rejects `"yes"` at `schema.tables[0].columns[0].generated`, and accepts `generated: true` on `text` (draft).
- [ ] Run them: RED. Implement; run: GREEN. `pnpm lint:fix`, `pnpm typecheck`, `pnpm test`. Commit `feat(core): add generated columns`.

### Task 3: Web — the store creates the id column

**Files:** modify `apps/web/src/lib/store/forge-store.ts`; tests in `tests/unit/lib/store/forge-store.test.ts` (existing tests choose `none` in `makeStore`).

**Interfaces — produces:** `ForgeState.settings: AppSettings`, `setNewTableId(id: NewTableId)`, `hydrateSettings(settings)`; `addTable` creates `{ name: 'id', type: integer|uuid, nullable: false, generated: true }` and sets it as the primary key unless `newTableId` is `none`.

- [ ] Write the failing tests: default settings are `integer`; `addTable` with `integer` yields one `id` column, integer, not nullable, generated, and `primaryKey` of it; with `uuid` the type is uuid; with `none` the table is empty (as before); `setNewTableId` changes only later tables; `hydrateSettings` replaces the settings; two tables get two different column ids.
- [ ] RED, implement, GREEN, lint, typecheck, test. Commit `feat(web): create a generated id column in new tables`.

### Task 4: Web — toolbar selector, inspector toggle, badge, persistence of the preference

**Files:** create `apps/web/src/lib/generated.ts`, `queries/settings/use-settings.ts`; modify `components/toolbar/toolbar.tsx`, `components/inspector/inspector.tsx`, `components/canvas/table-node.tsx`, `routes/index.tsx`, `styles.css`; test in `tests/unit/lib/generated.test.ts`.

**Interfaces — produces:** `supportsGenerated(type: ColumnType): boolean`, `typeChangePatch(column: Column, kind: ColumnKind): Partial<Omit<Column, 'id'>>` (new type; `generated` kept when the new kind supports it, cleared otherwise).

- [ ] Write the failing test for the two helpers (integer, bigint, uuid support it; text, varchar, numeric do not; the patch keeps `generated` from integer to uuid and clears it from integer to text and when absent).
- [ ] RED, implement the helpers, GREEN. Then wire the components (verified by typecheck, lint, build and the e2e of Task 5): the toolbar select bound to `settings.newTableId`, saved with `saveSettings` on change and read with `loadSettings` at startup; the inspector checkbox "Auto-generate" for supported kinds, using `typeChangePatch` when the type changes; the `auto` badge in the node. Commit `feat(web): choose the new-table id and toggle auto-generate`.
