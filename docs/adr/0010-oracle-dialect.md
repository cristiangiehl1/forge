# 0010. The Oracle dialect

Status: accepted

## Context

The team writes its Oracle migrations by hand (`sistema-recrutamento-selecao`): upper-case unquoted names, identity primary keys, named constraints, `CHECK` constraints where Oracle has no type. The diagram should produce scripts in that shape, from the same model that produces PostgreSQL.

## Decision

- **The dialect belongs to the project.** `Project` gains the optional `dialect` (`postgres` | `oracle`) and `options` (`uuid`: `raw16` or `varchar36`); a project saved without them is PostgreSQL, `formatVersion` stays 1, and they are written only when set. They are not part of the undo history.
- **The `Dialect` interface carries the SQL forms** (`tableParts`, `createIndex`, `constraintName`, `check`, `supportsUserTypes`), so the generator no longer hard-codes PostgreSQL and a new dialect is one module. PostgreSQL moved onto it with byte-identical output (the existing tests guard that); `generateDdl` now also returns `notes`.
- **Oracle 12.2 or newer.** Identity columns (`GENERATED BY DEFAULT ON NULL AS IDENTITY`), `IS JSON`, names up to 128 bytes. A column is `NAME TYPE [DEFAULT x | GENERATED ...] [NOT NULL]`, `NOT NULL` left out for primary-key and identity columns, `DEFAULT` before it.
- **Names** are upper case and unquoted when plain and not an Oracle reserved word; otherwise quoted with their exact text. Generated constraints are `PK_`, `FK_`, `CK_` plus table and column.
- **Types** follow the table in the spec: `NUMBER(10)`/`NUMBER(19)`/`NUMBER(5)`, `VARCHAR2`, `CLOB`, `NUMBER(1)` + `CHECK (… IN (0,1))` for a boolean, `RAW(16)` or `VARCHAR2(36)` for a uuid, `TIMESTAMP WITH TIME ZONE` for an instant, `CLOB` + `IS JSON` for json and arrays, `VARCHAR2` + `IN (…)` for an enum. Enums and domains are folded into their columns: no `CREATE TYPE`, no `CREATE DOMAIN`.
- **Notes, not failures.** What Oracle lacks is adapted and reported (arrays as JSON, `hash`/`gin`/`gist` as ordinary indexes, an index over a `CLOB`/`BLOB` not created, a value too long for `VARCHAR2`/`NUMBER`, a raw default copied as written). Only what Oracle refuses blocks the script: a primary key, unique index or foreign key over a `CLOB`/`BLOB`; names that collide once upper-cased; names over 128 bytes.
- **Import stays PostgreSQL-only**, and the dialog says so.

## Rejected

Oracle 11g (no identity: a sequence and a trigger per column; names of 30 bytes); features only in 23ai (native `BOOLEAN`, `JSON`, domains); always quoting names (every query would have to quote them).

## Consequences

- A new column kind needs a mapping in every dialect; the compiler's exhaustiveness checks find the missing ones.
- The Oracle script follows the team's conventions; it is not tested against a database here, and a setting such as `MAX_STRING_SIZE` can change what fits.
- `ON DELETE` actions are not in the model, so they are not written (the migrations use `ON DELETE CASCADE` often).
- Reading Oracle SQL back into the model is a separate piece of work.
